# MailWhere v0.9.0 — Preserve warm Ollama runners

## What changed
- Stopped forcing Ollama `num_ctx` on normal MailWhere LLM calls so an already-loaded OpenWebUI/CLI runner is not reloaded with a different context window.
- Stopped sending Ollama `keep_alive` by default so MailWhere does not override server/OpenWebUI/CLI runner lifetime policy.
- Kept adaptive `num_predict` output caps for shorter JSON responses without changing runner context.
- Changed default LLM batch concurrency from `2/4` to `1/1` so local Ollama scans prefer a stable already-loaded GPU runner over parallel VRAM pressure.
- Downgraded the legacy persisted `2/4` concurrency pair to `1/1`; users with enough VRAM can still set explicit parallel values such as `2/2`.
