# MailWhere v0.10.0 — Read-only CLI provider

## What changed
- Added `MailWhere.Cli`, a separate console provider for local automation and where-skills/Codex integration.
- Added JSON commands:
  - `health --json`
  - `manifest --json`
  - `export --json [--db PATH] [--archived-limit N]`
  - `list-tasks --json [--status open|archived|all] [--due-window today|overdue|7d|30d|none|all] [--limit N] [--db PATH]`
  - `list-review-candidates --json [--limit N] [--db PATH]`
- Added a read-only SQLite open path for CLI reads. The CLI checks for the database before opening it and never runs schema initialization.
- Added stable JSON envelopes with provider `MailWhere`, contract version `v1`, app version, generation timestamp, success data, and structured error code/message fields.
- Added stable exit codes: `0` success, `2` expected unavailable, `64` usage, `70` unexpected.
- Included `MailWhere.Cli.exe` in portable release builds and build manifests.

## Safety and privacy
- `MailWhere.Cli` references only `MailWhere.Core` and `MailWhere.Storage`; it does not reference `MailWhere.Windows` or `MailWhere.OutlookCom`.
- CLI commands do not load Outlook COM, open mailbox items, or mutate mailbox state.
- Missing DB returns `database-not-found` and does not create `followups.sqlite`, `followups.sqlite-wal`, or `followups.sqlite-shm`.
- CLI JSON omits raw body, source id/hash, evidence snippet, full recipient lists, prompt logs, and API keys.
