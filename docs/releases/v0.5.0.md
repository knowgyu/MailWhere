# MailWhere v0.5.0

## 변경 사항
- Ollama 요청에 `options.num_ctx=32768`을 명시해 서버 전역 256K context 설정과 별개로 MailWhere 스캔 요청의 context 예약량을 제한했습니다.
- batch 크기에 따라 `num_predict`/output token 예산을 `clamp(256 + batchCount * 160, 512, 4096)`으로 조정해 큰 batch JSON이 잘리는 실패를 줄였습니다.
- 메일 scan 중 준비/중복 확인과 저장은 직렬로 유지하고, 준비된 LLM batch 분석만 기본 2개 동시 요청으로 처리합니다. 고급 JSON 설정으로 `LlmInitialConcurrency`, `LlmMaxConcurrency`를 보존/조정할 수 있으며 v0.5.0 ceiling은 4입니다.
- LLM prompt에 제목/사유 길이 제한과 markdown/긴 인용 금지를 더 명시해 strict JSON 응답을 더 짧고 안정적으로 유도합니다.
- 동시 batch 상황에서도 source hash 예약과 저장 직전 중복 재확인으로 같은 메일/같은 업무가 재등장하는 것을 막습니다. SQLite 저장은 source/action signature 예약과 task/review 후보 저장을 하나의 transaction으로 묶습니다.

## 운영 메모
- 기본 동시성은 `LlmInitialConcurrency=2`, `LlmMaxConcurrency=4`입니다. v0.5.0에서는 AIMD/ramp가 아니라 고정 effective concurrency `min(initial,max)`를 사용하며 설정값은 1~4로 제한됩니다.
- Ollama 서버의 `OLLAMA_NUM_PARALLEL`이 2 이상일 때 스캔 throughput 개선이 가장 잘 나타납니다.
