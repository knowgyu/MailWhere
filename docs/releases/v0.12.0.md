# MailWhere v0.12.0 — Deterministic resume and local search window

## What changed

- Added a separate WPF **메일 검색** window launched from the main shell.
- Added SQLite-only query and Inbox/Sent/All folder filtering with at most 50 results.
- Added keyboard search, close, result navigation, and explicit source-open actions.
- Fixed equal-timestamp checkpoint resume by globally ordering inventory by
  `LastModifiedAt`, `StoreId`, and `EntryId` before checkpoint filtering and pagination.
- Expanded the managed-PC checklist for search states, stale sources, privacy,
  mailbox-unchanged evidence, and cancel/resume behavior.

## Safety and scope

- Search reads the existing SQLite mirror and does not activate Outlook.
- Outlook COM is used only after an explicit **원본 열기** action.
- StoreID and EntryID remain hidden from the UI and diagnostics.
- Outlook access remains read-only.
- No new dependency, service, background worker, database, attachment search,
  embedding, or COM pooling layer was added.
