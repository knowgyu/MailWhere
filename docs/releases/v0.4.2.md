# MailWhere v0.4.2 — visual follow-up and prompt payload polish

Status: implemented in repo and ready for the v0.4.2 release. Windows visual smoke is still recommended after publishing the release artifact.

## What changed

- Main board header buttons are grid-aligned, with `지금 메일 확인` kept as the stable rightmost primary action.
- Shared WPF button/card templates now use rounded MailWhere chrome instead of raw default focus rectangles.
- Board filter order is `오늘` → `이번 주` → `전체` → `날짜 없음`.
- old `검토 후보` user-facing copy is now `확인 필요`; retry copy is `AI 분석 다시 시도`.
- 확인 필요 window matches the main board tone and uses row actions `원본 열기`, `등록(Y)`, `나중에(S)`, `무시(I)`.
- 확인 필요 shortcuts are single-key at window level: `Y`, `S`, `I`, and `Esc`.
- Settings keeps developer tools visible under a local-test tab structure.
- LLM user payloads are metadata-first and content-last: static policy remains in the system prompt, long mail body fields move to final `content`/`contents`, and `now` is replaced with lower-churn date/timezone fields.

## Verification target

- Build, tests, static verification, and diff check must pass before pushing.
- Windows smoke still should capture main board, 확인 필요, settings, edit dialog, and toast before publishing a user-facing release asset.
