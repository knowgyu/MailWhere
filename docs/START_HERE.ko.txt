MailWhere 시작하기
=============================

1. 이 폴더의 MailWhere.exe 를 직접 실행하면 오늘 업무 보드가 열리고 tray에도 상주합니다. Windows 자동 시작은 tray만 띄웁니다.
2. tray 메뉴의 [열기]로 오늘 기준 업무 보드를 열 수 있고, [오늘 업무 보기]도 같은 화면으로 이어집니다.
3. 설정과 확인 필요 항목은 업무 보드 오른쪽 위 버튼으로 엽니다. 개발자 도구는 설정 창 안의 탭입니다.
4. 관리형 PC에서는 수동 메일 확인이 성공하고 운영 정책상 문제가 없을 때까지 [새 메일 자동 확인]을 켜지 마세요. 자동 확인은 Outlook 새 항목 이벤트를 먼저 감지하고, 놓친 이벤트는 설정한 간격의 cursor scan으로 보정합니다.
5. [지금 메일 확인]을 누르면 Online Archive를 제외한 Outlook Classic 기본 사서함의 모든 일반 메일 폴더를 read-only 검색 mirror로 이어서 동기화하고, 설정한 최근 기간(1/7/30/90일)의 Inbox/Sent에서는 할 일/일정/회신 대기 항목을 로컬 DB에 저장합니다.
6. 첫 검색 mirror 준비는 메일 양에 따라 오래 걸릴 수 있습니다. 확인 중에는 내용이 아닌 폴더/건수 진행 상태와 [확인 중지] 버튼이 표시되며, 중지 후 다시 실행하면 완료된 batch 다음부터 이어집니다.
7. 기본 08:00 오늘 업무 보드는 직접 열리거나 기존 보드를 오늘 보기로 갱신합니다. 보드 열기에 실패한 경우에만 오늘 브리핑 알림으로 대신 안내합니다.
8. 업무 보드는 [이번 주]가 기본이며 최근 7일 기한 미정도 함께 표시합니다. 오래된 기한 미정은 [미정 backlog]에서 정리합니다.
9. 각 업무 행의 [열기]는 가능한 경우 Outlook 원본 메일을 엽니다. [나중에]는 지정 시간까지 다시 표시하지 않고, [보관]은 active 목록에서 제외해 다시 자동 표시하지 않습니다. Outlook 원본 메일은 삭제하지 않습니다.
10. 업무 행 더블클릭으로 AI가 만든 제목과 기한을 바로잡을 수 있습니다. 저장(Enter), 취소(Esc)를 지원합니다. 유형은 내부에서만 유지합니다.
11. AI 분석은 기본 OFF입니다. Ollama native 또는 OpenAI-compatible endpoint 주소를 입력한 뒤 [모델 불러오기] → [연결 테스트] 순서로 확인하세요.
12. 인증이 필요한 AI 서버는 설정 창에서 [인증 없음], [API 키 입력], [환경 변수에서 읽기] 중 하나를 선택합니다.
13. AI 실패 시 기본값은 확인 필요에 남김입니다. AI 서버가 복구되면 확인 필요 창의 [실패한 AI 분석 다시 시도]로 다시 시도할 수 있습니다.
14. 기다리던 메일에 회신이 왔거나 내가 확인 답장을 보낸 것 같으면 확인 필요 창 안에서 [보관(Y)]/[유지(N)]로 정리합니다.
15. 로컬 업무/확인 필요 데이터를 지우려면 설정 > 개발자 도구의 [로컬 업무 데이터 삭제]를 사용하세요. 설정은 유지되고 Outlook 원본은 바뀌지 않습니다.
16. 팀 공통 endpoint/model을 배포하려면 MailWhere.defaults.sample.json을 MailWhere.defaults.json으로 복사해 수정한 뒤 exe와 같은 폴더에 두세요. 첫 실행 때 사용자 설정으로 복사됩니다.

포함 파일
- MailWhere.exe: 실행 파일
- appsettings.sample.json: 설정 예시
- MailWhere.defaults.sample.json: 팀/부서 기본 설정 seed 예시
- docs/: 운영/보안/검증 문서
- BUILD-MANIFEST.json: 빌드 정보

안전 경계
- 메일 발송/삭제/이동/답장/읽음 처리/첨부 자동 분석을 하지 않습니다.
- vendor-specific mailbox export 파일을 직접 파싱하지 않습니다.
- raw mail body와 prompt 로그를 저장하지 않습니다.
- MailWhere의 나중에/보관/업무 수정은 로컬 업무 상태만 바꿉니다.
